1. Requirements                                      *go-mod-requirements*

Neovim >=0.12 and Go >=1.27.3 on PATH are required. No external Lua dependencies
are needed.
The default icons need a Nerd Font; configure text icons if preferred.

Support and CI track the latest stable Go release; legacy Go toolchains are
not maintained. CI runs offline standalone specs with the latest stable Go
on Ubuntu with Neovim v0.12.0, and on Ubuntu and macOS with stable Neovim.

Dependency status is shown as virtual text on require entries in go.mod:
    outdated       A newer version is available for this module path.
    up_to_date     The current and latest versions compare equal.
    unpublished    The current version compares newer than the returned latest
                   version; this does not prove it was never published.
    error          The lookup or version comparison failed.

2. Setup                                                    *go-mod-setup*

With lazy.nvim: >lua
    {
      "syz51/go-mod.nvim",
      version = "*",
      ft = "gomod",
      opts = {},
    }
<
With another manager, install the plugin on your runtime path.
Initialization happens automatically on the first go.mod file. Explicit setup
is optional and lets you customize options: >lua
    require("go-mod").setup({ check_interval = 30 })
<
With auto_check enabled, setup also considers an already-open go.mod buffer.
Save your file and use :GoModCheck before starting an update.

LazyVim: create ~/.config/nvim/lua/plugins/go-mod.lua with a returned spec list: >lua
    return {
      {
        "syz51/go-mod.nvim",
        version = "*",
        ft = "gomod",
        opts = { check_interval = 60 },
      },
    }
<
Restart Neovim, run :Lazy install go-mod.nvim, and open go.mod. The filetype
loads the plugin; opts calls setup automatically. No custom config function,
Go extra, or Plenary dependency is needed. version = "*" follows stable tags;
:Lazy update go-mod.nvim updates it. Use tag = "v0.1.2" instead of version for
an exact pin.

3. Configuration                                    *go-mod-configuration*

Defaults: >lua
    require("go-mod").setup({
      icons = {
        outdated = "󰚰 ",
        up_to_date = "󰄬 ",
        unpublished = "󰚯 ",
        error = "󰅚 ",
      },
      virtual_text = {
        prefix = "●",
        spacing = 4,
      },
      highlights = {
        outdated = "DiagnosticWarn",
        up_to_date = "DiagnosticHint",
        unpublished = "DiagnosticInfo",
        error = "DiagnosticError",
      },
      auto_check = true,
      notify_on_load = true,
      check_interval = 60,
      log_level = "info",
      log_file = vim.fn.stdpath("cache") .. "/go-mod.log",
      max_concurrent_jobs = 4,
      timeout = 30000,
    })
<
virtual_text.prefix is displayed before status text; spacing is the number of
spaces separating virtual text from the source line. Highlights name existing
highlight groups.

auto_check enables automatic checks. check_interval is in MINUTES: a positive
value refreshes loaded go.mod buffers periodically, without requiring a buffer
switch. Set it to 0 to disable timer and re-entry refreshes while retaining the
initial automatic check. For manual checks only, set auto_check to false and
check_interval to 0.

notify_on_load shows an INFO notification titled go-mod.nvim when a loaded
buffer starts its first dependency version lookup. It applies to automatic and
manual checks, independently of log_level. Saves and later checks do not repeat
it; unloading and reloading the buffer resets it. Empty files, files with only
invalid versions, and checks cancelled before a lookup starts do not notify.
Set it to false to disable it.

max_concurrent_jobs limits concurrent version lookups. timeout is the per-Go-
process timeout in MILLISECONDS.

log_level accepts "trace", "debug", "info", "warn", or "error". log_file is a
file path; an empty string disables file logging. See |go-mod-troubleshooting|.

4. Commands and picker                                   *go-mod-commands*

*:GoModCheck*
    Check required module paths in the current go.mod buffer.

*:GoModToggle*
    Toggle dependency virtual text in the current buffer.

*:GoModUpdate*
    Open a picker of outdated modules from the current check results.

*:GoModUpdate-module*
    :GoModUpdate {module-path}
    Update one outdated module. Completion lists outdated module paths.

*:GoModLog*
    Open the configured log file. Set a nonempty log_file to enable file logging.

*:GoModSetup*
    Initialize with defaults. Usually unnecessary with automatic loading or
    an explicit setup() call.

Picker keys:                                             *go-mod-picker*
    Space, Enter    Toggle the module under the cursor.
    a               Toggle all selections.
    u               Update selected modules.
    U               Update all listed modules.
    Tab, Shift-Tab  Move between footer actions; Enter activates one.
    Esc, q, c       Close the picker.

Normal Neovim motions move between rows. No global mappings are installed.

Updates reject unsaved buffers and files changed since the check. Save, then
run :GoModCheck again if results are stale. Updates use the original go.mod
buffer's directory even after changing buffers or the working directory.
Selected versions are passed together to one go get command; Go resolves their
constraints as a group and conflicting selections fail. Results are refreshed
afterward. Inspect go.mod/go.sum and run your
project's tests after updating.

Avoid concurrent external edits while Go runs. Buffer edits made during an
update are preserved; reload and check again when ready.

5. Lua API                                                    *go-mod-api*

The public module is require("go-mod"). setup() accepts an optional options
table; the main user actions are also available as Lua functions: >lua
    local gomod = require("go-mod")
    gomod.setup({})
    gomod.check_dependencies()
    gomod.toggle()
    gomod.update_module("example.com/module")
    gomod.update_all_modules()
<
These calls operate on the current go.mod buffer by default. All four action
functions accept an optional buffer number (the second argument to
update_module). Run a check first to populate
update candidates. update_all_modules asks for confirmation before updating all
outdated modules. Use commands or these entry points rather than internal core,
UI, or updater state.

6. Go behavior                                           *go-mod-behavior*

Lookups query the original required module path upstream, including when a
replace directive exists. Local replacement contents are not checked for newer
upstream versions. Private or offline lookups may error.

Updates reject effective GOFLAGS containing -modfile, including persistent
settings from go env -w, because they redirect writes away from the open
go.mod. Remove the setting before updating with this plugin. External disk
changes after a check also require a reload and a fresh check.

Updates are performed by Go, which respects applicable replace directives.
The plugin does not rewrite replacements or automatically migrate module paths
and source imports across major-version boundaries, for example from
example.com/lib to example.com/lib/v2.

Go get may change transitive dependencies, go.sum, and, depending on the Go
version and project, Go or toolchain directives. Review the resulting diff.

Go follows the process and project environment: GOPROXY, GOPRIVATE, credentials,
workspace settings, and applicable Go configuration. Private registry access
must be configured outside this plugin.

Go module resolution and versioning reference: https://go.dev/ref/mod

7. Troubleshooting                                *go-mod-troubleshooting*

Run :checkhealth go-mod to inspect prerequisites and configuration.

- Check :echo executable('go') returns 1 and :set filetype? reports gomod.
- Save edits, then run :GoModCheck before updating.
- Run go list -m -json module/path@latest from the go.mod directory using the
  same environment as Neovim to investigate lookup or authentication errors.
- Use :GoModLog to inspect logs. The default path is stdpath("cache") followed
  by /go-mod.log. log_file = "" disables file logging.
- Temporarily set log_level = "debug" for more detail. Remove credentials,
  private module names, and private paths before sharing logs or bug reports.
- If icons are missing, install a Nerd Font or configure plain-text icons.
